# UI / HUD audit (round 1)

Auditor: UI/UX Designer. Audit only, no code changed. Branch `claude/uic-campus-game-plan-btnm3c`.
Method: code read of every HUD/screen file plus headless Chromium renders (software WebGL, `?quality=low`, port 5307) at 1366x768 and 1920x1080. Evidence images are in `screenshots/tmp/audit/ui/` (gitignored); older committed shots in `docs/screenshots/` are cited where they show the same state.

## Summary

The HUD works and is readable in the shots I could take: the squad panel, minimap, loot labels, spectate banner and match-end card are clean, use one font family and have text shadows. It is not yet "PUBG-clean" or "finished":

- **Missing feedback** for the actions that matter in a squad fight: revive (UI-01, UI-02), being hit (UI-04), hit confirmation (UI-05), ping (UI-03).
- **A new player gets no objective** and only a dev-flavoured 13 px key list (UI-07, UI-22).
- **Layout** differs from PUBG conventions (UI-10), the minimap is only a zone diagram with no heading (UI-06), and the kill feed is placed on top of the zone text (UI-17).
- **Consistency**: everything is inline styles with no shared tokens; accents, buttons, panels and z-indexes all differ (UI-12). Two finished-looking screens are never shown (UI-08).

Counts: 24 findings: 8 P1 (UI-01 to UI-07, UI-17), 16 P2, no P0.

### Top 5

1. UI-01/UI-02 revive has no prompt or progress and the downed banner gives the wrong instruction.
2. UI-04/UI-05 no damage direction, no flash, no real hitmarker.
3. UI-07 no objective or onboarding card; controls line is dev-style and incomplete.
4. UI-17 kill feed prints over the zone timer/phase text.
5. UI-06 minimap has no heading arrow and no map content.

### Coverage and limits

- Method: full read of `combat/hud.ts`, `squad/hud.ts`, `player/hud.ts`, `player/clickToPlay.ts`, `match/matchEndScreen.ts`, `squad/placementScreen.ts`, `boot/loading.ts`, `debug/perfOverlay.ts`, zone HUD in `zone/index.ts`, squad UI bits in `squad/adapter.ts`, `index.html`, `style.css`.
- Live renders at HEAD (software WebGL, `?quality=low&squad=bots`, 1366x768): `screenshots/tmp/audit/ui/01-loading-1366.png`, `02-spawn-clicktoplay-1366.png`. The shared machine was at load ~24 and Chromium crashed ("Target crashed") on the next steps, so the **pickup-after, ping, kill-feed, F3, downed, spectate, match-end, Play-again and 1920x1080 states were not rendered live**. For those I used the committed screenshots in `docs/screenshots/` (`campus-loot-hud.png`, `s4-squad-hud.png`, `spectate-bot1.png`, `match-end-wipe.png`, `squad-bots-start.png`; 1280x720, from earlier commits) plus code geometry. Findings that rest on geometry rather than a render (UI-17, UI-22 overlap, UI-13) say so.
- Not yet checked: downed/crawl view, revive in progress, ping on a distant target, dark-interior vs bright-sky contrast at 1920, Play-again state after restart (the zone HUD is rebuilt, `perfOverlay.ts:21`). Suggest QA re-check these after fixes with the `qa-*` viewpoints.
- Severity key: P0 blocks play or looks broken; P1 breaks a Quality Bar line (feedback, first-time player, overlap); P2 polish/consistency.
